# Pitch and explainer

Use post-implementation when you need buy-in or approval. Reviewers start with the same unknowns you started with — an explainer that shows you accounted for them (and for the failure points they'd have anticipated) speeds up approval.

**Example prompt:**

- "Package the prototype, the spec, and the implementation notes into a single doc I can drop in [Slack/email] to get buy-in. Lead with the demo."

Skip this for small changes — it's worth the artifact only when someone else needs to approve or understand the work without reading the full diff.
