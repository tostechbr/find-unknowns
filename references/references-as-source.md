# References

Use when you can't describe what you want in enough detail, either because you lack the vocabulary or it would take too long to spell out.

The best reference is source code, not a diagram, doc, or screenshot. Point at a folder and say what to look for, even in a different language — code carries markup and structure a screenshot can't.

**Example prompt:**

- "This [module/crate/service] in [path] implements the exact [behavior] I want. Read it and reimplement the same semantics in [target]."

If you're about to describe a behavior in prose instead of pointing at an implementation of it, check whether a reference exists first.
